# Sandbox (Полигон) 🏗️

Мой личный полигон и архивная песочница для хранения, тестирования и каталогизации независимых проектов, наработок и экспериментов. 

Каждый проект изолирован, находится в своей директории внутри `projects/` и имеет собственную структуру, сборочные скрипты и документацию.

---

## 🛠️ Автоматизация управления (runner.py)

В корне репозитория находится Python-скрипт `runner.py`, который выступает в роли единого CLI-интерфейса для создания, сборки и тестирования проектов на основе их локальных сценариев `workflow.py`.

### Доступные команды

* **Посмотреть доступные шаблоны:**
    ```bash
    ./runner.py list
    ```
* **Создать новый проект по шаблону:**
    ```bash
    ./runner.py new <имя_шаблона> <имя_проекта>
    ```
* **Собрать конкретный проект или всё сразу:**
    ```bash
    ./runner.py build <имя_проекта>
    ./runner.py build --all
    ```
* **Запустить тесты для конкретного проекта или всех сразу:**
    ```bash
    ./runner.py test <имя_проекта>
    ./runner.py test --all
    ```

---

## 📁 Структура репозитория

* `projects/` — все изолированные проекты и песочницы.
* `templates/` — шаблоны для быстрого старта новых экспериментов (копируются через `runner.py new`).
* `runner.py` — оркестратор сборки и тестирования.

---

## ⚙️ Анатомия проекта (workflow.py)

Чтобы проект поддерживался глобальным раннером, внутри его папки должен находиться файл `workflow.py`, реализующий интерфейс автоматизации:

```python
# Пример структуры workflow.py внутри проекта
def dependencies():
    return {"os": ["linux", "macos"]}  # Ограничение по OS (опционально)

def build():
    return ["mkdir -p build", "cd build && cmake .. && make"]

def tests():
    return ["cd build && ctest"]
```

Если проект старый или чисто архивный (без автосборки), runner.py просто пропустит его при массовых командах с флагом --all, если в нём нет workflow.py.
